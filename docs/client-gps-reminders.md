# Optional half-hour reminders and low-power position checks

The optional client reminder is now independent of GPS. Existing opt-in is retained in `client_gps_reminder_state.enabled`; the native settings label is “Promemoria a 30 minuti”. The minute cron `client-gps-reminders` still calls `queue_due_gps_reminders_v1()`. For the current native customer installation with granted notification permission, it queues one reminder in the 25–30 minute interval before a confirmed, non-completed/non-no-show appointment. Ordinary salon-configured reminders are unchanged. Missing, stale, inaccurate, nearby or moving GPS observations never suppress this reminder.

The existing `(appointment_id, appointment_at)` ledger deduplicates jobs and permits a reminder after a real time change. `_dedupeKey` includes both values so an earlier ordinary reminder does not suppress this extra reminder. Failed enqueue/no device does not consume the ledger. A composition uses its first current component only, not one reminder per phase. An unpaid booking has no appointment; a non-accepted linked booking is excluded explicitly.

Native clients no longer start background location updates, ask for Always permission, or create a location foreground service. At OTA startup and on app state changes, the previous `salonpro-client-gps-reminders-v1` task is stopped. Any residual old task callback stops its service instead of uploading a sample.

Only with an already granted foreground position permission, a valid durable native customer session and a server-authorized appointment window may the app start `watchPositionAsync`. `get_client_gps_reminder_window_v1` exposes only the current installation's window, from 35 to 25 minutes before the first appointment component. The client refuses malformed or longer windows, stops at a hard deadline, on background/inactive, logout, revoked consent, missing appointment or network verification failure. Foreground polling revalidates eligibility every minute; the timer does not promise to wake a suspended app. Coordinates are not stored; optional recent samples can enrich the same single reminder for a distant stationary user.

Disabling stops device tracking immediately. Offline revocation is saved locally and replayed on the next connected foreground activation. The server cannot learn an offline change immediately, so the UI reports that online synchronization remains needed. No location is collected while revocation is pending. Preference writes are serialized to prevent an old disable response from racing a new enable.

The source change uses existing Expo Location, TaskManager and SecureStore modules. No native configuration, entitlement, runtime version or permission expansion is included; it is an OTA change for the existing 1.0.20/1.0.21 production runtimes, standard and Terminal variants. Existing OS background permission may remain granted but is not exercised by this reminder code. A future binary may remove obsolete background capability declarations after coordinating other location-dependent features.

Verification: actual controller/native-adapter runtime tests cover both platforms, legacy service cleanup, hard deadline, asynchronous races, logout through actual native-session code, offline disable replay and web inactivity. Server scheduling, actual production push queue, deduplication, no-GPS fallback, opt-out, composition and permission rules are tested in a transaction with rollback and synthetic device tokens. Real device delivery and battery profiling are distinct checks; do not claim them from SQL, unit tests or an OTA package.
